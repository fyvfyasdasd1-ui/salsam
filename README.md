# Salsam — Windows в вашем ритме

C# / .NET 8 / WPF, MVVM, русский тёмный интерфейс. Каждое изменение сначала попадает в очередь: его можно исключить галочкой. Перед применением показывается подтверждение. Прирост FPS не обещается.

## Запуск без установки

Готовый файл: `artifacts/portable-x64/Salsam.exe`. Скопируйте **только этот EXE** на компьютер с Windows 10/11 x64 и запустите двойным щелчком. .NET, Visual Studio, DLL рядом с EXE и подключение к Интернету для запуска не нужны. ARM64 и 32-битная Windows этой сборкой не поддерживаются.

При первом запуске встроенные библиотеки распакуются в пользовательский TEMP; запуск может занять несколько секунд. Папки TEMP и LOCALAPPDATA должны быть доступны для записи. Оптимизации применяются после выбора и подтверждения. EXE не подписан цифровой подписью. Работа интерфейса на настоящей Windows ещё не проверена в этой Linux-среде.

## Архитектура

- `src/Salsam.Core`: журнал с атомарной заменой файла, сохранение исходного значения перед изменением, чтение результата, откат с проверкой внешних изменений, расчёт метрик времени кадра.
- `src/Salsam.App`: WPF, MainViewModel, команды и привязки. WindowsBackend отделён от представления через ISettingBackend; использует штатные powercfg, HKCU Run и PowerShell/CIM. MonitorService использует Windows API.
- `tests/Salsam.Checks`: исполняемые проверки ядра без сторонних пакетов.
- `tests/Salsam.WindowsChecks`: проверки настоящего HKCU Run, карантина и датчиков. Создают собственные временные данные и убирают их в finally; существующие записи автозагрузки не меняются.

## Сборка и запуск на Windows 10/11

Установите .NET 8 SDK из официального источника Microsoft. В Visual Studio нужна нагрузка «Разработка классических приложений .NET», но сама Visual Studio необязательна. Выполните из корня репозитория:

```powershell
dotnet build src/Salsam.App/Salsam.App.csproj -c Release
dotnet run --project src/Salsam.App -c Release
dotnet run --project tests/Salsam.Checks -c Release
dotnet run --project tests/Salsam.WindowsChecks -c Release
```

Приложение запускается обычным пользователем (asInvoker). Если политика запрещает действие, показывается ошибка; автоматического повышения прав нет. Windows-проверки выполняйте при закрытом приложении.

Сборка единого автономного EXE Windows x64:

```powershell
dotnet publish src/Salsam.App/Salsam.App.csproj -p:PublishProfile=Portable -o artifacts/portable-x64
```

Запускайте `artifacts/portable-x64/Salsam.exe`. Профиль Portable включает runtime, управляемые и native-библиотеки в файл, не использует trimming и не требует соседних файлов. Исходные проекты и тесты для разработки по-прежнему требуют SDK.

## Возможности и ограничения

| Возможность | Реализация |
| --- | --- |
| Оборудование | CPU, GPU и версия драйвера GPU, RAM, диски и Windows через CIM |
| Питание | Переключение только существующих схем с проверкой активной схемы и откатом |
| Профили | «Сбалансированный» и «Игры» добавляют соответствующую существующую схему в очередь. «Свой профиль» — ручная очередь; постоянное сохранение пока не реализовано |
| Автозагрузка | HKCU Run текущего пользователя, описание и издатель из метаданных exe, отключение выбранной записи и восстановление строки и типа |
| Очистка | Просмотр файлов верхнего уровня пользовательского TEMP старше 7 дней, перенос выбранных в карантин, восстановление без перезаписи конфликтующих файлов |
| Мониторинг | Общая загрузка CPU и физической RAM каждые 2 секунды |
| Измерения | Импорт CSV времени кадра, средний FPS, 1% low и графики до/после на общей шкале |
| Восстановление | Журнал, отдельный откат, откат всех в обратном порядке, проверка наличия точек Windows |

Журнал и карантин: `%LOCALAPPDATA%\Salsam`. Не удаляйте папку, если нужен откат. Второй экземпляр в пользовательском сеансе блокируется. Ошибка прекращает последующие операции; выполненные остаются в журнале. При конфликте с внешним изменением откат отменяется.

Игровой режим и фоновая запись открываются в штатных настройках; их состояние автоматически не определяется. Ручные изменения Windows в журнал не попадают. Управление сторонними оверлеями, датчики GPU/диска/температуры, захват FPS в реальном времени и создание точек восстановления не реализованы — интерфейс явно это показывает.

Карантин на том же диске **не освобождает место**; необратимое удаление не реализовано. Очистка не обходит подкаталоги TEMP, личные документы, сохранения и кэши шейдеров. Заблокированные файлы принудительно не удаляются. Defender, обновления, брандмауэр, службы, HPET, таймеры, сетевой стек и «очистка RAM» не затрагиваются.

## CSV

Простой CSV с разделителем `,` или `;`, без разделителей внутри значений. Заголовок FrameTimeMs или MsBetweenPresents; положительные конечные миллисекунды с десятичной точкой. Минимум 100 кадров **одного процесса**. Экспортируйте отдельно нужную игру и исключите строки инициализации с нулевым временем. Смешение процессов автоматически не обнаруживается.

FPS = 1000 / среднее время кадра. 1% low = 1000 / среднее время самых медленных 1% кадров, число округляется вверх. На графике длинные записи группируются с сохранением максимума группы. Сравнивайте одинаковые сцену, настройки, разрешение, прогрев и длительность; импорт не доказывает причинную связь с оптимизацией.

## Проверка на Windows

1. Проверьте оборудование и изменения CPU/RAM под нагрузкой.
2. Добавьте другую доступную схему. Исключите её галочкой: применение недоступно. Включите, подтвердите и проверьте powercfg /getactivescheme. Выполните откат и проверьте снова.
3. Запустите WindowsChecks для проверки автозагрузки и карантина на собственных тестовых данных.
4. Импортируйте реальные CSV одной игры; проверьте обе линии и отсутствие показателей до импорта.
5. Проверьте окно при 100%, 150%, 200% DPI, поиск, навигацию, прокрутку и отказ в операциях при ограничивающей политике.

## Облачная среда

В Linux успешно собрана WPF Release-версия с Windows targeting; 14 проверок ядра прошли. Окно WPF, системные операции и WindowsChecks в Linux **не запускались**. Их работа на Windows требует проверки.

SDK: `/workspace/.dotnet`. Для команд задайте DOTNET_CLI_HOME=/workspace/.dotnet-cli и NUGET_PACKAGES=/workspace/.nuget/packages, чтобы не писать в недоступный домашний каталог. Linux поддерживает редактирование, сборку и проверки ядра; GUI требует Windows.
